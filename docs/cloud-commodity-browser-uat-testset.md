# 云商品浏览器用户视角验收测试集

用途：用于在 `http://localhost:3001/` 通过浏览器模拟真实用户操作，验证云商品 Agent 是否能基于新增用户故事、补充口径和 demo 数据完成端到端业务协同。

验收原则：所有场景都应走正常 Agent 链路，允许模型调用工具、查询数据、生成 OpenUI 和文本总结，但不应依赖页面写死答案。写入类动作只允许生成草稿、审批摘要或模拟计划，不得表现为真实生产变更。

## 0. 全局操作规范

每条用例按下面方式执行：

1. 打开 `http://localhost:3001/`。
2. 在顶部场景切换中选择「云商品」。
3. 按用例要求切换角色。若当前没有对应角色，使用最接近的可选角色模拟：
   - 商品 PM / GTM / SRE：优先使用「程一川 / 云商品产品经理」。
   - 老板 / 财务 BP：优先使用「许闻达 / 业务负责人」或当前老板类角色。
   - 销售 / 解决方案：优先使用云销售角色。
   - 客户自助：使用「自助客户 / 云商品自助客户」。
4. 点击新会话，输入该步骤的问题。
5. 等待回答完成，检查 OpenUI、正文、权限、数据边界和字段中文化。
6. 在同一剧本中连续提问时，不要中途切换业务域；需要换角色时保留同一业务域。

统一通过标准：

- 回答不出现 `cloud_*`、`owner_user_id`、`severity=high`、`arr_at_risk_cny`、`linked_entities` 等工程字段。
- 表格列名、指标名、风险标签、流程节点都使用中文业务说法。
- 估算和报价必须出现公式、假设、边界、置信度和“非正式报价/演示数据”说明。
- 老板类问题必须出现结论、GMV/毛利/风险、影响金额或客户、负责人、下一步动作、证据来源。
- OpenUI 不支持时可以降级文本，但文本仍应结构化、中文友好、可追溯。

## 1. 新品上市前夜：Seedance Mini 自助购买上线

业务目标：验证商品 PM、财务、SRE、GTM 和老板能围绕同一个新品上线风险形成闭环。

### 1.1 IPD 上架检查

操作：

1. 场景选择「云商品」。
2. 角色选择「程一川 / 云商品产品经理」。
3. 输入：`Seedance Mini 准备从产品能力商品化为可自助购买的云商品，IPD 上架前有哪些检查点还没完成？`

目标输出：

- OpenUI：横向流程图或 IPD readiness checklist。
- 必须包含：商品范围、购买页字段、价格/资源包、容量/队列、SLA/法务、GTM ready。
- 每个检查点应有状态、负责人、缺口和下一步。
- 数据边界说明为“演示数据/估算假设”，不得暗示官方库存或正式流程。

### 1.2 价格和折扣互斥

操作：

1. 继续同一会话或新会话。
2. 输入：`Seedance Mini 自助购买入口上线前，价格、资源包和合同折扣怎么做互斥？`

目标输出：

- OpenUI：标签组件、风险列表或价格规则表。
- 必须包含：促销价、资源包、合同折扣的互斥关系。
- 必须说明：毛利底线、审批动作、哪些折扣销售不能直接承诺。
- 不应只返回价格明细表。

### 1.3 大促队列健康

操作：

1. 角色仍为商品 PM 或模拟 SRE。
2. 输入：`Seedance Mini 大促生成队列健康度不够，应该怎么限流、告警和通知销售？`

目标输出：

- OpenUI：容量/队列健康看板、告警标签或流程图。
- 必须包含：限流策略、告警阈值、SRE 动作、销售通知、客户沟通边界。
- 不能误答成套餐推荐或预算拆分。

### 1.4 活动页禁承诺项

操作：

1. 模拟 GTM 角色。
2. 输入：`Seedance Mini 大促活动页需要哪些销售禁承诺项和数据边界提示？`

目标输出：

- OpenUI：FAQ/标签/清单。
- 必须包含：不可承诺固定产能、不可承诺固定交付时间、估算非正式报价、demo 数据边界。
- 应给出活动页文案级建议，语气面向客户而不是工程调试。

### 1.5 延期经营影响

操作：

1. 切换老板类角色。
2. 输入：`Seedance Mini 上线如果延期一天，会影响哪些客户、GMV 和销售动作？`

目标输出：

- OpenUI：经营影响卡片、风险排序或 GMV 影响图。
- 必须包含：影响客户、影响金额、销售动作、负责人、下一步。
- 应说明影响是 demo/mock 口径。

## 2. Agent Plan 用量爆了：套餐毛利与客户体验冲突

业务目标：验证套餐 GMV、成本毛利、用量告警和客户超额付费解释是否能连起来。

### 2.1 GMV 与用量健康

操作：

1. 场景选择「云商品」。
2. 角色选择老板类角色。
3. 输入：`Agent Plan 本月 GMV、pipeline、毛利和用量告警健康吗？最大风险是谁负责？`

目标输出：

- OpenUI：GMV 漏斗、KPI 卡、风险列表。
- 必须包含：GMV 目标、已成交、pipeline、毛利率、用量告警、最大风险、负责人、下一步动作。

### 2.2 毛利打穿风险

操作：

1. 模拟财务 BP。
2. 输入：`Agent Plan 高成本模型、联网搜索和视频生成会不会把毛利打穿？`

目标输出：

- OpenUI：成本构成图、毛利风险标签或风险列表。
- 必须包含：高成本模型、联网搜索、视频生成三类成本项。
- 必须说明毛利风险、审批动作和哪些承诺不能直接给销售。
- 不允许出现 HTTP 402 或“暂时无法回答”。

### 2.3 用量告警联动

操作：

1. 模拟 SRE。
2. 输入：`Agent Plan 用量告警翻倍，如何联动客服、销售和客户确认？`

目标输出：

- OpenUI：流程图或任务看板。
- 必须包含：告警确认、客户通知、销售跟进、客服解释、财务/超额付费确认。

### 2.4 客户超额付费解释

操作：

1. 切换「自助客户 / 云商品自助客户」。
2. 输入：`Agent Plan 套餐额度用完后会自动扣费吗？我要怎么确认超额付费？`

目标输出：

- 文本或 OpenUI 均可。
- 必须明确：是否自动扣费、谁确认、如何开启/关闭、账单如何提示。
- 不应误答成“Agent Plan Medium 能对话多少轮”的估算问题。

## 3. 金融客户大单：ECS GPU + RDS + TOS + CLB

业务目标：验证从销售方案、容量评审、财务折扣、运维阻塞到老板经营目标的完整成交链路。

### 3.1 销售方案

操作：

1. 场景选择「云商品」。
2. 角色选择云销售或模拟销售。
3. 输入：`金融客户预算 30 万，优先稳定性和可审计，ECS GPU、RDS、TOS、CLB 应该怎么组合？正式报价前要确认什么？`

目标输出：

- OpenUI：预算构成图、方案表、检查清单。
- 必须只围绕 ECS GPU、RDS、TOS、CLB，不混入 Seedance/Agent Plan。
- 必须包含预算拆分、关键假设、报价边界和正式报价前检查项。
- 表格预算列不得显示为 `-`。

### 3.2 容量限售

操作：

1. 模拟解决方案或 SRE。
2. 输入：`华东 1 和新加坡的 GPU 容量能支撑首批客户吗？如果容量不足，发布和销售应该怎么限制？`

目标输出：

- OpenUI：容量图表、区域风险标签、限售建议。
- 必须包含：华东 1、新加坡、容量覆盖率、灰度/限售、负责人、下一步。

### 3.3 财务折扣边界

操作：

1. 模拟财务 BP。
2. 输入：`这个 ECS GPU 包月套餐的价格和折扣会不会影响毛利？哪些折扣不能直接给销售承诺？`

目标输出：

- OpenUI：毛利卡片、折扣边界、审批任务。
- 必须包含：毛利底线、折扣审批阈值、合同折扣边界、销售禁承诺项。

### 3.4 运维事件经营影响

操作：

1. 模拟 SRE。
2. 输入：`如果新加坡 GPU 容量不足导致交付延期，影响哪些订单、GMV 和客户？给我回滚和客户沟通方案。`

目标输出：

- OpenUI：事件影响看板、订单表、回滚流程图。
- 必须包含：受影响订单、客户、GMV/收入确认影响、延期小时数、客户沟通方案、回滚检查点。

### 3.5 老板 GMV 目标

操作：

1. 切换老板类角色。
2. 输入：`ECS GPU 商品本月 GMV 目标完成得怎么样？毛利、交付、容量和客户风险分别谁负责？`

目标输出：

- OpenUI：GMV target cockpit。
- 必须包含：GMV 目标、已成交、缺口、pipeline、净收入、毛利率、延期订单、容量健康度、客户风险、负责人、下一步动作。
- 不应只展示容量风险看板。

## 4. 客户账单争议：从客户问题到经营风险

业务目标：验证客户自助权限、销售解释、财务风险和老板经营指标是否一致。

### 4.1 客户查账单

操作：

1. 场景选择「云商品」。
2. 角色选择「自助客户 / 云商品自助客户」。
3. 输入：`查询我能看的 2026 年 6 月账单和发票状态。`

目标输出：

- 只展示该客户可访问范围内的账单/发票。
- 若无数据，应提示“你可访问范围内暂无对应账单/发票”。
- 不应返回“缺少 cloud:read”。

### 4.2 销售解释争议

操作：

1. 切换云销售角色。
2. 输入：`星河传媒集团这个月 CDN/TOS 账单有什么争议？我下一步该怎么跟客户解释？`

目标输出：

- OpenUI：账单争议表、客户沟通建议。
- 必须包含：争议金额、争议原因、客户解释口径、负责人、下一步。

### 4.3 财务看争议

操作：

1. 模拟财务 BP。
2. 输入：`有哪些客户账单或发票有争议？影响金额是多少，谁负责解决？`

目标输出：

- OpenUI：争议金额 KPI、客户列表、负责人。
- 必须包含：客户、金额、账单/发票状态、负责人、处理动作。

### 4.4 老板经营口径

操作：

1. 切换老板类角色。
2. 输入：`云商品平台本月 GMV、净收入、毛利率、活跃客户和账单争议金额分别是多少？哪些指标需要解释为 demo 假设？`

目标输出：

- OpenUI：经营驾驶舱。
- 必须包含：GMV、净收入、毛利率、活跃客户、账单争议金额、demo/mock 边界。

## 5. 续约保卫战：重点客户 ARR 风险闭环

业务目标：验证续约风险金额、客户排序、销售动作、客户成功模板沉淀。

### 5.1 老板看续约风险

操作：

1. 场景选择「云商品」。
2. 角色选择老板类角色。
3. 输入：`哪些重点云客户续约有风险，影响金额是多少？`

目标输出：

- OpenUI：续约风险榜或风险表。
- 必须包含：客户名称、风险金额、续约概率、风险原因、负责人、下一步。
- 不允许只显示风险等级和日期。

### 5.2 销售本周跟进

操作：

1. 切换云销售角色。
2. 输入：`我负责的云客户里，本周最该跟进哪三个机会？请按续约风险、金额和下一步动作排序。`

目标输出：

- OpenUI：Top 3 客户列表。
- 必须包含排序原因、金额、风险等级、下一步动作、截止时间。

### 5.3 客户成功影响

操作：

1. 模拟客户成功。

目标输出：

- OpenUI：影响客户、GMV、升级路径和补救动作。

### 5.4 模板沉淀

操作：

1. 模拟 PM。
2. 输入：`把这些续约风险沉淀成下一次商品上架和客户成功检查模板。`

目标输出：

- OpenUI 或文本：检查模板。
- 必须拆成“商品上架检查模板”和“客户成功检查模板”。
- 必须包含可复用 checkpoint，而不是重复展示续约卡片。

## 7. 权限边界挑战：不同角色看同一个客户

业务目标：验证 domain 和 role scope 同时生效。

### 7.1 客户视角

操作：

1. 场景选择「云商品」。
2. 角色选择「自助客户 / 云商品自助客户」。
3. 输入：`查询我能看的 2026 年 6 月账单和发票状态。`

目标输出：

- 只能看到自己的账单/发票。
- 不显示其他客户名称、合同价或内部折扣。

### 7.2 销售视角

操作：

1. 切换云销售角色。
2. 输入：`查询我能看的云客户续约风险和下一步跟进动作。`

目标输出：

- 只展示销售可访问客户。
- 必须包含客户、金额、风险原因、下一步。

### 7.3 老板视角

操作：

1. 切换老板类角色。
2. 输入：`有哪些客户账单或发票有争议？影响金额是多少，谁负责解决？`

目标输出：

- 可展示经营汇总和负责人。
- 不泄漏工程字段。
- 敏感合同细节按权限展示或脱敏。

### 7.4 场景隔离

操作：

1. 切换到「经销商」场景。
2. 输入：`当前云商品平台有哪些高风险事项？给我负责人、影响客户和下一步动作。`

目标输出：

- 应提示：当前在经销商场景，这个问题属于云商品，请切换到云商品场景。
- 不应调用云商品工具。
- 不应显示“已调用云商品但没有数据”。

- 必须包含：估算非正式报价、资源包/促销/合同折扣边界、产能不承诺、发票/合同说明。

### 8.4 复盘模板

操作：

1. 切换老板类角色。
2. 输入：`把 Seedance Mini 从上架、销售、交付、经营风险复盘成下一次商品上架模板。`

- OpenUI：复盘流程图或模板清单。
- 必须包含：IPD checkpoint、GTM ready、财务毛利、SRE 容量、客服通知、销售报价、经营指标复盘。

## 9. 快速冒烟用例

当时间有限时，只跑以下 6 条：

1. 云商品 PM：`Seedance Mini 准备从产品能力商品化为可自助购买的云商品，IPD 上架前有哪些检查点还没完成？`
2. 云销售：`金融客户预算 30 万，优先稳定性和可审计，ECS GPU、RDS、TOS、CLB 应该怎么组合？正式报价前要确认什么？`
3. 老板：`ECS GPU 商品本月 GMV 目标完成得怎么样？毛利、交付、容量和客户风险分别谁负责？`
4. 自助客户：`查询我能看的 2026 年 6 月账单和发票状态。`
5. 老板：`哪些重点云客户续约有风险，影响金额是多少？`
6. 经销商场景：`当前云商品平台有哪些高风险事项？给我负责人、影响客户和下一步动作。`

快速冒烟目标：

- 至少 4 条出现 OpenUI。
- 不出现工程字段泄漏。
- 不出现 domain 混淆。
- 不出现 HTTP 402。
- 不出现文本结论和 OpenUI 明细冲突。

## 10. 验收结果分级

通过：

- 目标输出全部满足，OpenUI 和文本一致，权限与场景隔离正确。

条件通过：

- 核心业务结论正确，但存在轻微展示问题，例如公式符号、列宽、个别标签不够友好。

不通过：

- 路由到错误工具或错误业务域。
- 权限错误或越权。
- 老板/销售/客户关键问题无法回答。
- OpenUI 泄漏工程字段、JSON 碎片或与文本结论矛盾。
- 写入类问题表现为真实执行生产动作。
