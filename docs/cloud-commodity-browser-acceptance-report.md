# 云商品浏览器验收记录与优化方案

验收时间：2026-06-20  
验收入口：http://localhost:3001/  
验收方式：在内置浏览器中以用户视角操作页面，切换业务域和角色，连续输入云商品用户故事问题，观察回答、OpenUI、权限和场景隔离表现。

## 已执行验收

### 1. 云商品风险总览

操作：

1. 切到「云商品」场景。
2. 使用「程一川 / 云商品产品经理」。
3. 输入：`当前云商品平台有哪些高风险事项？给我负责人、影响客户和下一步动作。`

预期：

- 展示云商品风险列表或经营驾驶舱。
- 风险等级、风险类型、负责人、影响客户、下一步动作均为中文业务表达。
- 不出现底层表 key、字段 key、JSON 片段或工程枚举。

实际：

- 有 OpenUI，但展示效果不达标。
- 顶部风险卡多处显示「云商品风险信号」「中」「low」，风险等级不一致。
- 明细中出现 `margin`、`capacity`、`renewal` 等英文枚举。
- 明细中出现 `{\"\": \"\"}` 形式的 JSON 碎片。

结论：不通过。OpenUI query/risk 投影需要专门修复。

### 2. ECS GPU GMV 目标与经营健康

操作：

1. 仍在「云商品」场景。
2. 输入：`ECS GPU 商品本月 GMV 目标完成得怎么样？毛利、交付、容量和客户风险分别谁负责？`

预期：

- 进入 ECS GPU GMV 目标驾驶舱。
- 输出 GMV 目标、已成交、缺口、pipeline、净收入、毛利率、延期订单、容量健康度、客户风险、负责人和下一步动作。

实际：

- 回答进入「ECS GPU 容量风险看板」，只展示地域容量池、可用 GPU 卡、峰值覆盖率和限售策略。
- 没有回答 GMV 目标完成情况、pipeline、毛利和客户风险负责人。

结论：不通过。ECS GMV 问题被 agentic fallback/工具选择误路由到容量风险评审。

### 3. 金融客户 ECS + RDS + TOS + CLB 方案

操作：

1. 输入：`金融客户预算 30 万，优先稳定性和可审计，ECS GPU、RDS、TOS、CLB 应该怎么组合？正式报价前要确认什么？`

预期：

- 推荐 ECS GPU、RDS、TOS、CLB 的组合。
- 展示预算拆分、关键假设、报价边界、正式报价前检查项。
- 文本结论与 OpenUI 表格一致。

实际：

- OpenUI 明细行正确展示了 ECS、RDS、TOS、CLB。
- 预算分配图正确显示 144000 / 66000 / 54000 / 36000。
- 但表格「预算」列显示为 `-`。
- 文本结论写成「建议组合 Seedance + Agent Plan + TOS + CDN」，与 ECS/RDS/TOS/CLB 明细冲突。
- 后续解释也混入了 Seedance/Agent Plan 的内容行业话术。

结论：不通过。方案工具数据和报告 composer/OpenUI 字段映射不一致。

### 4. 预算自助估算

操作：

1. 输入：`10000 元预算能生成多少秒视频？Agent Plan Medium 能对话多少轮？`

预期：

- 展示 Seedance 视频秒数和 Agent Plan 对话轮数。
- 包含公式、假设、边界、置信度、非正式报价说明。

实际：

- OpenUI 展示「云商品自助询价」。
- 包含预计视频秒数、视频条数、对话轮数、置信度。
- 包含公式、假设、边界和非正式报价说明。
- 文本中的 Seedance 公式乘号在部分位置丢失，影响可读性。

结论：基本通过，但公式文本渲染需要优化。

### 5. 自助客户账单/发票权限

操作：

1. 切换角色到「自助客户 / 云商品自助客户」。
2. 输入：`查询我能看的 2026 年 6 月账单和发票状态。`

预期：

- 自助客户只能看到自己可访问客户范围内的账单和发票。
- 若无数据，提示“未找到你可访问范围内的账单/发票”。
- 不应直接报权限缺失。

实际：

- 页面返回：`你没有权限查看该数据（缺少：cloud:read）。`
- 当前数据文件中 `cloud_customer_001` 配置了 `cloud:read`，但浏览器实际角色上下文没有正确带入或权限链路被覆盖。

结论：不通过。自助客户账单权限链路需要修复。

### 6. 业务域隔离

操作：

1. 切到「经销商」场景。
2. 角色自动变为「林悦 / 销售」。
3. 输入：`当前云商品平台有哪些高风险事项？给我负责人、影响客户和下一步动作。`

预期：

- 不应调用云商品工具。
- 应提示当前在经销商场景，请切换到云商品场景后再问云商品问题。

实际：

- 返回：`已调用云商品经营简报工具，但没有拿到可展示数据。`
- 经销商场景中仍尝试执行云商品能力，用户体验像系统故障。

结论：不通过。agentic fallback 和工具调用层需要统一 selected_domain gate。

### 7. Seedance 上线前夜补测

操作：

1. 切回「云商品」场景。
2. 使用「程一川 / 云商品产品经理」。
3. 连续输入：
   - `Seedance Mini 自助购买入口上线前，价格、资源包和合同折扣怎么做互斥？`
   - `Seedance Mini 大促生成队列健康度不够，应该怎么限流、告警和通知销售？`
   - `Seedance Mini 大促活动页需要哪些销售禁承诺项和数据边界提示？`

预期：

- 价格互斥问题应输出价格护栏、资源包/促销/合同折扣互斥规则、毛利底线和审批动作。
- 队列健康度问题应输出限流、告警、SRE 动作、销售通知和客户沟通口径。
- 活动页问题应输出 FAQ、不可承诺项、估算边界、正式报价边界和数据说明。

实际：

- 价格互斥问题只返回「最近有 15 条相关记录」和一个破损价格表，表头只有 `SKU / 计费项 / 地域 / 价格类型 / 单价`，没有互斥规则、毛利底线或审批动作。
- 队列健康度问题被路由到「云商品方案推荐」，输出 Seedance + Agent Plan + TOS + CDN 预算拆分，没有回答限流、告警、SRE 或销售通知。
- 活动页禁承诺项也被路由到「云商品方案推荐」，没有输出活动页 FAQ、不可承诺边界或数据提示。

结论：不通过。Seedance 运营/SRE/GTM 场景缺少稳定 intent/tool 映射和专用报告模板。

### 8. Agent Plan 用量与毛利补测

操作：

1. 输入：
   - `Agent Plan 本月 GMV、pipeline、毛利和用量告警健康吗？最大风险是谁负责？`
   - `Agent Plan 高成本模型、联网搜索和视频生成会不会把毛利打穿？`
   - `Agent Plan 套餐额度用完后会自动扣费吗？我要怎么确认超额付费？`

预期：

- GMV 健康问题应展示目标、已成交、pipeline、毛利、用量告警、风险负责人和下一步动作。
- 毛利打穿问题应输出高成本模型、联网搜索、视频生成等成本项对毛利的影响和财务审批动作。
- 超额付费问题应明确不会自动扣费，必须管理员/客户二次确认，并展示客户友好说明。

实际：

- GMV 健康问题表现较好：进入「Agent Plan 套餐 GMV 目标驾驶舱」，包含 GMV、已成交、pipeline、毛利率、用量告警和风险排序。
- 毛利打穿问题返回：`这个问题暂时无法直接给出答案（agentic LLM HTTP 402）`，没有本地 deterministic / tool fallback。
- 超额付费问题错误进入「云商品自助询价」，展示 Seedance 秒数和 Agent Plan 轮数，没有回答自动扣费、二次确认或超额付费开关。

结论：部分通过。Agent Plan 经营驾驶舱可用，但财务毛利和客户超额付费解释链路不达标。

### 10. 上线复盘与事故闭环补测

补测背景：

- 浏览器测试过程中 `3001` 服务曾断开，页面连续返回 `请求失败：Failed to fetch`。
- 重启服务后，`cloud_commodity` domain pack 正常加载，再次执行复盘类问题。

操作：

1. 保持「云商品」场景。
2. 使用「程一川 / 云商品产品经理」模拟 SRE、PM、GTM、老板连续输入：
   - `Seedance Mini 上线后如果生成失败率升高，商品页和销售话术应该怎么降级？`
   - `生成 Seedance Mini 自助购买发布审批摘要，包含风险、人审、回滚和客服通知。`
   - `Seedance Mini 官网落地页应该放哪些 FAQ，避免客户把估算当正式报价？`
   - `把 Seedance Mini 从上架、销售、交付、经营风险复盘成下一次商品上架模板。`

预期：

- 事故降级问题应输出商品页降级、销售话术、告警、客服通知、回滚检查点。
- 发布审批摘要应输出风险、人审、回滚、客服通知，并强调只生成草稿。
- 官网 FAQ 应输出客户可读 FAQ、禁承诺项、估算边界和正式报价边界。
- 复盘模板应沉淀为下一次商品上架模板，覆盖 IPD、GTM、财务、SRE、客服、销售、经营指标。

实际：

- 事故降级问题返回：`Intent Router 未能完成路由，已停止处理：router LLM HTTP 402`，没有 deterministic fallback。
- 发布审批摘要能调用工具并展示「云商品审批摘要」，但正文直接泄漏完整 JSON，其中包含 `approval_summary`、`release_request_id`、`change_type`、`status`、`blocked`、`mocked` 等工程字段。
- 发布审批摘要包含人审和回滚，但没有清晰的客服通知内容。
- 官网 FAQ 表现较好，能输出 GTM 销售包、客户 FAQ、不可承诺项、报价前检查和演示边界。
- 官网 FAQ 仍出现 `draft` 等英文状态值，字段中文化不完整。
- 复盘模板问题误路由到「云商品上架字段清单」，只输出商品字段、Offer/SKU、计费项、购买页字段，没有形成“下一次商品上架模板”。
- 复盘输出仍出现 `model`、`video_input`、`prod_seedance`、`Provider=volcengine` 等工程字段或供应商绑定表达。

结论：不通过。上线复盘链路中 FAQ 场景基本可用，但事故降级、审批展示清洗和复盘模板沉淀均不达标。

## 技术优化方案

### 1. 强化 selected_domain 全链路隔离

目标：

- 当前选中经销商时，云商品 intent、agentic fallback 和云商品专用工具都不能执行。
- 用户明显问其他 domain 时，返回友好提示，而不是调用失败。

改动建议：

- 在 agentic fallback 选择阶段增加 selected_domain 过滤：fallback 定义需声明 `domain_id`，不匹配时不参与规划。
- 在云商品 fallback `match` 函数中显式读取 selected domain；非 `cloud_commodity` 时直接不匹配。
- 对 domain mismatch 的用户可见文案统一为：`当前在「经销商」场景。这个问题属于「云商品」，请切换到云商品场景后继续。`
- 增加浏览器/自动化回归：经销商场景问云商品风险，不应出现“已调用云商品”。

### 2. 修复自助客户权限链路

目标：

- `cloud_customer_001` 在浏览器角色切换后应带上 `cloud:read`、`cloud:estimate` 和 `accessible_customer_ids`。
- 自助客户只能查询自己的账单/发票。

改动建议：

- 检查 `/api/chat` 用户解析是否优先使用 `user_id` 对应的 `data/users.json`，避免被 wecom/mock 用户覆盖权限。
- 检查前端切换角色后请求体是否携带正确 `user_id` 和 `domain_id`。
- 在云商品 permission policy 中保留客户 scope，但不要对客户自助账单场景误判缺少 `cloud:read`。
- 增加回归：用 `cloud_customer_001` 查询 2026-06 账单，结果只包含 `cust_ai_studio` 或友好空结果。

### 3. 修复 ECS GMV 目标路由优先级

目标：

- 包含 “GMV 目标 / 目标完成 / 毛利 / 交付 / 客户风险” 的 ECS 问题优先调用 `cloud_gmv_target_briefing`。
- 只有明确问容量、SRE、限售、灰度时才调用 `cloud_capacity_risk_review`。

改动建议：

- 调整 cloud agentic fallback 顺序：`cloud_gmv_target_briefing` 放在 `cloud_capacity_risk_review` 前。
- 在 capacity fallback 中增加排除条件：出现 `GMV`、`目标`、`毛利`、`客户风险`、`经营健康` 时不匹配。
- 在 deterministic rules 中提高 `cloud.gmv.target_briefing` 优先级，并覆盖“毛利、交付、容量和客户风险分别谁负责”这类老板问法。
- 增加回归：ECS GPU GMV 问题必须返回 `gmv_briefing`，OpenUI 为 GMV target cockpit。

### 4. 修复云商品风险 OpenUI 投影

目标：

- 风险列表展示为“风险名称 / 风险等级 / 风险类型 / 负责人 / 影响 / 下一步动作”。
- 不再显示 `low`、`margin`、`capacity`、JSON 碎片。

改动建议：

- `cloudQuerySurface` 针对 `cloud_risk_signals` 不要直接把 friendlyRow 后的任意对象塞进 `riskItems`。
- 为 risk signal 增加专用 mapper：
  - `risk_type` → 毛利风险 / 容量风险 / 续约风险 / 合规风险 / 流程风险
  - `severity` → 高风险 / 中风险 / 低风险
  - `linked_entities` → 关联对象摘要，不展示原始 JSON
  - `recommended_actions` → 中文动作列表
- `riskItems` 只消费标准字段：`message`、`level`、`owner`、`impact`、`action`。
- 增加 OpenUI 覆盖测试：风险查询输出不包含 `margin|capacity|renewal|{\"`。

### 5. 修复方案推荐文本与表格一致性

目标：

- 金融/ECS 场景文本、图表、表格都展示 ECS/RDS/TOS/CLB。
- 内容行业场景才展示 Seedance/Agent Plan/TOS/CDN。

改动建议：

- `cloud_solution_recommendation` 输出中增加 `scenario_type: infra | content`。
- report composer 根据 `solution.package_plan` 动态生成“推荐组合”，不要写死 Seedance/Agent Plan。
- OpenUI 表格预算列改用 `budget_cny`，避免列名为「预算」但 row key 不匹配导致显示 `-`。
- 增加回归：金融客户方案回答不得包含 Seedance/Agent Plan，除非用户问题明确提到。

### 6. 优化估算公式展示

目标：

- 公式在 OpenUI 和正文中都保持可读，不丢乘号。

改动建议：

- 公式不要直接走 Markdown 普通文本；使用 code span 或公式字段单独渲染。
- 文本报告中将 `*` 转为 `×`，避免 Markdown 解析吞掉星号。
- 增加回归：估算回答必须包含 `×` 或 code 格式公式，并包含“非正式报价/不承诺固定产能”。

### 7. 补齐 Seedance 运营/GTM/SRE 专用链路

目标：

- Seedance 价格互斥、队列健康、活动页禁承诺问题不再落到通用方案推荐。

改动建议：

- 新增或强化 deterministic rules：
  - `价格/资源包/合同折扣/互斥/促销` → 价格护栏/毛利风险报告。
  - `队列/限流/告警/通知销售/大促` → 容量或运维健康报告。
  - `活动页/FAQ/禁承诺/数据边界` → GTM package draft。
- 为 Seedance 价格护栏增加专用 report composer：输出互斥规则、毛利底线、审批动作和不可承诺项。
- 为队列健康增加 OpenUI：队列健康度、限流策略、告警对象、通知销售动作、客户沟通边界。

### 8. 补齐 Agent Plan 财务/客户解释 fallback

目标：

- Agent Plan 毛利和超额付费问题不依赖在线 agentic LLM，也不误入自助估算。

改动建议：

- 新增 deterministic rule：
  - `高成本模型/联网搜索/视频生成/毛利打穿` → GMV/毛利风险 briefing 或风险信号查询。
  - `额度用完/自动扣费/超额付费/二次确认` → 客户解释 playbook。
- 增加 `cloud_agent_plan_overage_policy_briefing` 或复用 answer playbook，输出：
  - 是否自动扣费。
  - 谁确认。
  - 开通草稿/审批摘要边界。
  - 账单页和客户通知口径。
- 当 agentic LLM 402 时，云商品 report composer 应基于风险信号/回答策略样例生成兜底答案。

### 9. 补齐续约风险视图和模板沉淀

目标：

- 续约风险必须面向老板/销售/客户成功可用，而不是低信息量卡片。

改动建议：

- 为 `cloud_renewal_opportunities` 增加专用 OpenUI mapper：
  - 客户名称：通过 customer_id 关联客户主数据。
  - 风险金额：`forecast_next_arr_cny` 或 `current_arr_cny`。
  - 续约概率、风险等级、风险原因、负责人、下一步。
- 新增续约 report composer：
  - 老板问题按金额/概率排序。
  - 销售问题按“本周最该跟进”排序。
  - 复盘问题输出“商品上架检查模板 + 客户成功检查模板”。
- 增加回归：续约回答不得只显示日期和风险等级，必须包含客户、金额、负责人和动作。

### 10. 补齐上线事故降级与复盘模板链路

目标：

- Seedance 上线后失败率升高、商品页降级、销售话术降级、客服通知、回滚和复盘模板类问题必须有稳定 fallback。
- 复盘模板类问题不能误路由到商品建模字段清单。

改动建议：

- 新增 deterministic rules：
  - `失败率升高/降级/事故/客服通知/销售话术` → `cloud_ops_incident_business_impact` 或 Seedance 运维降级报告。
  - `复盘/下一次模板/商品上架模板/客户成功模板` → 复盘模板 composer，而不是商品模型 draft。
- 新增或扩展 report composer：
  - 事故降级报告输出：触发条件、商品页降级、销售话术、客服通知、SRE 告警、回滚检查点、客户影响和经营影响。
  - 上线复盘报告输出：IPD checkpoint、GTM ready、财务毛利、SRE 容量、客服通知、销售报价、经营指标复盘。
- 发布审批摘要正文只输出中文摘要，不直接透出原始 JSON；原始结构可保留在 debug 模式。
- 审批摘要补充客服通知字段：通知对象、触发条件、客户话术、负责人。
- 增加回归：发布审批摘要不得包含 `approval_summary|release_request_id|change_type|mocked|blocked` 等原始字段。

### 11. 增加本地服务稳定性验收

目标：

- 浏览器验收过程中服务断开应被识别为运行时稳定性问题，且页面应有更友好的恢复提示。

改动建议：

- 在前端请求失败时区分网络断开、后端 4xx/5xx、router/LLM 错误，给出不同提示。
- 后端 `/health` 或轻量状态接口用于浏览器验收前检查服务是否可用。
- 浏览器验收脚本先执行健康检查，再开始场景问题。
- 开发服务启动方式在文档中统一为可用命令，避免 `npm`/`pnpm` 环境不一致导致启动失败。

## 建议验收门禁

修复后重新跑以下浏览器用例：

1. 云商品风险总览：不能出现英文枚举或 JSON 碎片。
2. ECS GPU GMV 目标：必须出现 GMV、毛利、pipeline、容量、客户风险负责人。
3. 金融客户方案：文本和表格都为 ECS/RDS/TOS/CLB。
4. 自助客户账单：客户能看到自己范围内数据或友好空结果。
5. 经销商场景问云商品：提示切换场景，不调用云商品工具。
6. 估算问题：公式、假设、边界、置信度和非正式报价均完整。
7. Seedance 价格互斥问题：必须输出互斥规则、毛利底线和审批动作。
8. Seedance 大促队列问题：必须输出限流、告警、SRE 和销售通知。
9. Agent Plan 毛利问题：不能出现 HTTP 402，必须输出成本项和毛利风险。
10. Agent Plan 超额付费问题：必须回答是否自动扣费和二次确认方式。
11. 续约风险问题：必须展示客户、金额、概率、负责人和下一步动作。
12. Seedance 事故降级问题：必须输出商品页降级、销售话术、客服通知、SRE 告警和回滚检查点。
13. 发布审批摘要：不得泄漏 JSON/工程字段，必须包含客服通知和“只生成草稿”边界。
14. 上线复盘模板：必须输出可复用 checkpoint，不得误路由到商品字段清单。

自动化建议：

- 扩展 `cloud-openui-coverage`：增加风险查询 raw key 泄漏断言。
- 扩展 `domain-isolation`：覆盖 agentic fallback 场景。
- 新增 `cloud-browser-acceptance` 或 Playwright 脚本，覆盖场景切换、角色切换和 6 条核心浏览器用例。
