# 云商品产商品工作手册与学习大纲

定位：这份大纲面向初入云商品行业的人，不把云商品平台讲成抽象白皮书，而是从“怎么把一个能力变成可售商品、怎么协同上线、怎么经营、怎么处理异常、怎么服务客户”的工作现场出发。

适用对象：

- 产品经理：理解产品化、商品化、主数据、上架、GTM、经营复盘。
- 研发/平台工程：理解商品中台、订单计量账单链路、权限、工作台、集成边界。
- 财务 BP / 法务 / SRE / GTM / 销售 / 客户成功：理解自己在云商品链路中的输入、输出、审批和风险。
- 新人学习者：快速建立云商品行业的业务地图、术语地图和协作地图。

核心学习目标：

- 能分清“能力、产品、商品、Offer、SKU、计量项、价格、权益、订单、账单”的关系。
- 能完整讲清一个云商品从产品化定义到发布、售卖、交付、经营复盘的闭环。
- 能识别每个环节的负责人、交付物、卡点、风险和检查口径。
- 能从研发、产品、上下游协同方、客户和经营层视角审视一个云商品平台是否完整。

## 0. 学习路线总览

建议学习顺序：

1. 先学概念：能力、产品、商品、Offer、SKU、Meter、Price、Plan、Entitlement。
2. 再学主数据：商品中台维护什么，下游系统消费什么。
3. 再学生命周期：产品化、商品化、上架、渠道发布、销售、交付、账单、续约、下线。
4. 再学协同关系：产品、研发、财务、法务、SRE、GTM、销售、客服、客户成功、老板。
5. 再学异常反向链路：改规格、改价、退款、退订、账单争议、事故、回滚、巡检。
6. 最后学经营管理：GMV、净收入、毛利、ARR、续约、稳定性、覆盖率、竞争力、目标达成。

新人不要一开始陷入系统字段。正确入口是先理解业务闭环，再反推数据和系统。

## 1. 云商品基础概念

本章目标：建立术语地图，避免把产品、商品、套餐、价格、资源包混在一起。

必须掌握：

- 产品能力：底层技术能力或资源能力，例如模型推理、GPU 实例、对象存储、CDN 分发。
- 产品：被定义清楚的能力边界、目标客户、交付方式、SLA 和成本模型。
- 商品：可以被购买、报价、计费、交付、开票和续约的商业对象。
- Product：商品主对象，描述“卖的是什么”。
- Offer：售卖方案，描述“怎么卖”，例如按量、包月、资源包、企业套餐、试用包。
- SKU：可购买规格，描述“买哪一档”，例如 ECS 2C4G、Agent Plan Medium。
- Meter：计量项，描述“按什么消耗”，例如 Token、秒数、GB、请求次数、实例小时。
- Price：价格规则，描述“多少钱”，包括目录价、阶梯价、合同价、促销价。
- Entitlement：权益规则，描述“买了之后拥有什么额度和规则”。
- Subscription：订阅关系，描述客户当前购买和生效的商品权益。

学习重点：

- Offer 不是 SKU，Offer 是售卖包装，SKU 是规格。
- Meter 不是 Price，Meter 记录用量，Price 决定如何把用量变成金额。
- 官网不是商品主数据来源，官网是渠道。商品中台和产品定义才是源头。

练习问题：

- 一个 Agent Plan Medium 应该拆成哪些 Product、Offer、SKU、Meter、Price 和 Entitlement？
- 一个 ECS GPU 包月商品和一个 Seedance 视频生成资源包，在主数据结构上有什么不同？

## 2. 产品化定义前置

本章目标：先判断“能力能不能成为产品”，再谈商品上架。

典型问题：

- 这个能力是否已经是一个合格产品？
- 目标客户是谁？
- 核心场景是什么？
- 能承诺什么，不能承诺什么？
- 成本输入、SLA、交付能力是否成立？

关键交付物：

- 产品化 readiness review。
- 产品定义草稿。
- 目标客户与核心场景说明。
- 能力边界和不可承诺项。
- SLA 初稿。
- 成本测算输入。
- 交付物清单。

主要负责人：

- 商品 PM：牵头产品定义和边界。
- 研发/算法/资源团队：说明能力范围和技术限制。
- SRE：确认稳定性、容量和交付窗口。
- 财务 BP：确认成本输入和毛利底线。
- 法务/合规：确认承诺边界和合同表述。

重难点：

- 技术能力不等于产品。能调用 API，不代表能自助购买、能计费、能交付。
- 产品定义缺失时，后续上架、销售、账单、客服都会出问题。
- 不可承诺项必须前置，不要等销售卖出后再补救。

练习问题：

- Seedance Mini 目前只是模型能力，是否具备产品化条件？
- ECS GPU 训练实例需要哪些产品化交付物，才能进入商品化上架？

## 3. 商品主数据模型

本章目标：理解云商品平台最核心的数据对象。

核心实体：

- 产品族：产品在更大能力体系中的归类，例如计算、存储、网络、AI、数据库。
- Product：商品主数据。
- Offer：售卖方案。
- SKU：规格。
- Spec：规格参数。
- Meter：计量项。
- Price：价格。
- Region：地域和可售范围。
- Customer：客户。
- Contract：合同。
- Subscription：订阅。
- Order / Order Item：订单和订单明细。
- Metering Record：计量记录。
- Bill / Invoice：账单和发票。
- Release Request：发布申请。
- Approval Task：审批任务。
- Risk Signal：风险信号。
- Workflow Task：流程任务。
- Renewal Opportunity：续约机会。

每个实体都要掌握：

- 它是什么。
- 谁维护。
- 谁消费。
- 主键和展示字段是什么。
- 改了它会影响哪些下游。
- 哪些字段可以对客户展示，哪些只能内部使用。

重难点：

- 商品主数据不只是后台表单，它会驱动官网、控制台、销售报价、订购、计量、账单、合同和客服解释。
- 字段没有中文业务说明时，前台容易暴露工程 key，用户体验会很差。
- source、mock、confidence 等数据边界字段必须保留，但对用户要转写成“演示数据、估算假设、置信度”。

练习问题：

- 如果 Offer 的计费模式从按量改为包月，会影响哪些 SKU、价格、订购、合同和账单？
- 哪些字段应该由商品中台维护，哪些字段应该由财务、SRE、法务或销售维护？

## 4. 主数据治理与血缘

本章目标：理解商品平台为什么是“中台”，而不是一个录入后台。

治理问题：

- 谁是主数据源？
- 字段归属方是谁？
- 哪些下游系统消费这个字段？
- 字段变更影响哪些客户、合同、账单和渠道？
- 哪些字段需要审批后才能生效？

关键交付物：

- 主数据血缘图。
- 字段归属矩阵。
- 下游消费系统清单。
- 字段变更影响分析。
- 主数据完整性校验报告。
- 渠道一致性检查报告。

主要负责人：

- 商品 PM：定义字段业务含义。
- 平台研发：维护数据模型、接口和一致性校验。
- 下游系统负责人：确认消费口径。
- 财务/SRE/法务/销售：维护各自专业字段。

重难点：

- 官网、控制台、销售报价、API/Marketplace、账单系统看到的字段不一定相同。
- 价格、计费模式、权益额度、地域可售、SLA 文案都是高风险字段。
- 主数据变更必须能追溯，不能只靠口头同步。

练习问题：

- Seedance Mini 官网介绍页、控制台购买页和销售报价单分别应该消费哪些商品主数据？
- Agent Plan 的每日赠送额度调整，会影响哪些下游系统？

## 5. Offer、SKU、Meter、Price 设计

本章目标：掌握云商品商业包装的核心设计方法。

Offer 设计问题：

- 这个产品应该设计几个 Offer？
- 按量、包月、资源包、试用包、企业套餐能否同时存在？
- Offer 和 SKU、Meter、Price、Contract 的关系是否一致？
- 折扣、促销、资源包、合同价能否叠加？

常见 Offer 类型：

- 按量 Offer：用多少付多少。
- 包月 Offer：固定周期、固定权益或规格。
- 资源包 Offer：预付费购买一定额度。
- 企业套餐 Offer：按组织、席位、用量或合同组合。
- 试用 Offer：低门槛获客，但需要防滥用。
- 超额付费 Offer：套餐额度用完后的补充购买。

关键交付物：

- Offer 设计方案。
- Offer-SKU-Meter-Price 关系图。
- 冲突和互斥规则。
- 可售状态管理。
- 折扣审批边界。
- 正式报价前检查清单。

重难点：

- 不能只看“能不能卖”，还要看“怎么计量、怎么开票、怎么解释、怎么退款”。
- Plan 型产品会同时涉及权益、额度、过期、超额、账单解释，复杂度高于单品型产品。
- 销售希望灵活，财务和法务要求边界，平台需要把规则固化。

练习问题：

- Agent Plan 应该设计几个 Offer？
- Seedance Mini 的资源包、促销价和合同折扣如何做互斥？

## 6. Plan 型产品与权益治理

本章目标：单独掌握套餐、会员和权益型产品的特殊复杂度。

必须回答的问题：

- 每天什么时候发放权益？
- 未用完是否过期？
- 退订后是否还能用？
- 退款时赠送权益如何处理？
- 能否叠加合同折扣？
- 超额是否自动扣费？
- 客户如何二次确认？
- 账单中如何解释赠送和消耗？

关键交付物：

- 权益规则表。
- 额度发放规则。
- 消耗顺序规则。
- 过期、退订、退款规则。
- 超额付费确认页。
- 账单解释模板。
- Plan 毛利穿透分析。

主要负责人：

- 商品 PM：定义权益规则和客户体验。
- 财务 BP：确认赠送成本、收入确认和毛利底线。
- 研发：实现权益发放、消耗、冻结、过期和账单关联。
- 客户成功/客服：解释客户争议。
- 法务：确认权益承诺和退款边界。

重难点：

- “每天送 50 元等值 Token”不是一句营销文案，而是一套权益系统规则。
- 超额付费默认不应自动扣费，应该客户管理员二次确认。
- 客户感知的是“我还剩多少、为什么扣这么快、为什么过期”，不是内部计量公式。

练习问题：

- Agent Plan Medium 额度用完后会发生什么？
- 会员每日赠送 Token 会带来哪些财务、法务和客户体验风险？

## 7. 产品生命周期全流程

本章目标：把一个云商品从 0 到 1，再从 1 到 N 的完整链路讲清楚。

标准流程：

1. 产品能力识别。
2. 产品化定义。
3. IPD 立项和 PRD。
4. 商业测算。
5. 商品模型设计。
6. Offer、SKU、Meter、Price 设计。
7. 权益和合同规则设计。
8. SRE 上架门禁。
9. 法务和合规审查。
10. GTM 和销售 enablement。
11. 渠道发布。
12. 灰度上线。
13. 订单、交付、计量、账单验证。
14. 发布后巡检。
15. 经营复盘和版本迭代。
16. 续约、扩容、下线或替换。

每个环节要看四件事：

- 输入是什么。
- 输出交付物是什么。
- 负责人是谁。
- 失败或阻塞时怎么处理。

关键交付物：

- IPD checkpoint。
- 商品建模草稿。
- 发布申请。
- 风险审查。
- 审批摘要。
- 回滚检查点。
- 灰度计划。
- 发布后巡检报告。
- 复盘模板。

重难点：

- 生命周期不是线性流水线，财务、SRE、法务和销售会反复把问题打回产品定义。
- 发布不是终点，订单、计量、账单、客户反馈正常，才算上线稳定。
- 所有高风险动作都应该先生成草稿和审批摘要，不直接生产变更。

练习问题：

- ECS GPU 训练实例从立项到上架，需要哪些 checkpoint？
- Seedance Mini 上线延期一天，会影响哪些客户、GMV 和销售动作？

## 8. 渠道发布与上下游协同

本章目标：理解不同渠道看到的不是同一张表，而是同一套主数据的不同投影。

主要渠道：

- 工作台：内部 PM、财务、SRE、销售、老板使用的协同入口。
- 官网：营销获客和公开介绍渠道。
- 控制台：客户自助购买、配置、查看用量和账单的入口。
- API / Marketplace：生态销售、自动化订购和第三方集成入口。
- 销售解决方案：大客户售前、方案包、报价单和合同协同。
- 客服/客户成功：解释账单、处理争议、续约和用量健康。

每个渠道要回答：

- 展示哪些字段？
- 禁止展示哪些字段？
- 字段来源是什么？
- 是否需要审批后发布？
- 是否与其他渠道一致？
- 客户看到后会如何理解？

关键交付物：

- 渠道发布矩阵。
- 官网 FAQ。
- 控制台购买页字段。
- 销售报价前检查清单。
- Marketplace 上架资料。
- 客服解释话术。
- 渠道一致性巡检。

重难点：

- 官网是销售/营销渠道，不是商品能力来源。
- 控制台购买页字段必须和计量、价格、权益、账单一致。
- 销售方案可以灵活组合，但不能越过财务、SRE、法务边界。

练习问题：

- Seedance Mini 发布到官网、控制台、销售和 Marketplace，各渠道应该展示哪些字段？
- 哪些字段不能对客户展示？

## 9. GTM、销售方案与客户成交

本章目标：理解商品不是上架后自动成交，需要 GTM 和销售方案把商品带到客户场景里。

GTM 内容：

- 目标客户分层。
- 行业场景。
- 核心卖点。
- 竞品边界。
- 套餐组合。
- FAQ。
- 销售禁承诺项。
- 正式报价前检查清单。

销售方案内容：

- 客户预算。
- 业务场景。
- 地域和合规要求。
- SLA 要求。
- 产品组合。
- 预算拆分。
- 报价假设。
- 风险和边界。
- 下一步动作。

主要负责人：

- GTM/运营：行业包、话术、FAQ。
- 销售：客户需求、预算、决策人、推进节奏。
- 解决方案：产品组合和架构建议。
- 财务：折扣边界和毛利。
- SRE：容量和交付窗口。
- 法务：合同承诺边界。

重难点：

- 大客户要方案和合同，小客户要自助购买和清晰解释。
- 销售想承诺更多，平台要确保能交付、能计费、能解释。
- 正式报价必须区别于估算草稿。

练习问题：

- 金融客户预算 30 万，ECS GPU、RDS、TOS、CLB 应该怎么组合？
- 内容行业客户预算 2 万，Seedance 和 Agent Plan 怎么分配？

## 10. 财务商业化与经营口径

本章目标：理解 GMV 好看不等于经营健康。

核心指标：

- GMV。
- 净收入。
- ARR / MRR。
- 毛利率。
- 活跃付费客户。
- Pipeline。
- 续约风险金额。
- 账单争议金额。
- 折扣率。
- 资源包消耗率。
- 收入确认风险。

财务口径：

- 按量收入确认。
- 包月收入确认。
- 资源包递延收入。
- 免费额度成本归集。
- 高成本模型调用成本。
- 折扣、促销、合同价叠加。
- 退款、退订和补偿券。
- 毛利底线审批。

关键交付物：

- 商业测算表。
- 毛利底线。
- 折扣审批规则。
- 收入确认口径。
- 资源包递延规则。
- 经营健康看板。
- 财务风险清单。

重难点：

- Plan 型产品最容易出现免费额度和高成本能力把毛利打穿。
- 资源包收入和消耗需要递延和结转，不是收款即收入。
- 大客户折扣可能帮助 GMV，但拉低净收入和毛利。

练习问题：

- Agent Plan 高成本模型、联网搜索和视频生成会不会把毛利打穿？
- ECS GPU 包月折扣能不能直接承诺给销售？

## 11. SRE 上架门禁与稳定性

本章目标：理解 SRE 不是“上线后救火”，而是商品可售前的稳定性门禁。

SRE 必须确认：

- 容量是否足够。
- 队列是否健康。
- 限流策略是什么。
- 告警阈值是什么。
- 灰度比例是多少。
- 回滚触发条件是什么。
- SLA 能承诺到什么程度。
- 客服和销售通知机制是什么。

关键交付物：

- SRE readiness checklist。
- 容量评审。
- 告警阈值。
- 限流策略。
- 灰度计划。
- 回滚方案。
- SLA 边界。
- 事故客户沟通模板。

重难点：

- 不能承诺未经确认地域的固定交付日期。
- 运维事件会影响 GMV、收入确认、客户满意度和续约。
- SRE 口径必须同步到销售话术、官网、控制台和合同。

练习问题：

- Seedance Mini 大促生成队列不健康，应该怎么限流、告警和通知销售？
- 新加坡 GPU 容量不足，会影响哪些订单、GMV 和客户？

## 12. 客户自助购买与售后解释

本章目标：站在客户视角理解云商品，不只站在平台视角。

客户买前会问：

- 我买的是套餐、资源包还是按量？
- 这个价格是不是正式报价？
- 预算能买多少？
- 交付时间能保证吗？
- 用完会不会自动扣费？

客户买后会问：

- 为什么账单比估算高？
- 赠送 Token 为什么过期？
- 为什么生成失败还扣费？
- 为什么这个地域不能购买？
- 为什么合同价和控制台价不同？

关键交付物：

- 客户友好解释模板。
- 买前确认页。
- 超额付费确认页。
- 账单解释模板。
- 账单争议处理流程。
- 客户可见字段过滤规则。

重难点：

- 客户不理解内部字段和计费公式，需要业务语言解释。
- 估算、演示数据、参考价格和正式报价必须区分。
- 客户自助场景必须严格权限隔离，不能看到其他客户合同价或账单。

练习问题：

- Agent Plan 套餐额度用完后会自动扣费吗？
- 为什么 Seedance 账单高于预算估算？

## 13. 异常链路、反向链路与治理

本章目标：掌握云商品平台日常最常见的非正向流程。

典型异常：

- 改规格。
- 新增 SKU。
- SKU 下线。
- Offer 改名。
- 调价。
- 套餐权益调整。
- 地域扩容或下线。
- 退款。
- 退订。
- 账单争议。
- 计量异常。
- 发票异常。
- 发布失败。
- 容量不足。
- SLA 事故。

每个异常都要看：

- 触发原因。
- 影响客户。
- 影响合同。
- 影响账单。
- 影响渠道展示。
- 是否影响收入确认。
- 是否需要客户通知。
- 是否可回滚。

关键交付物：

- 变更影响分析。
- 审批摘要。
- 存量客户影响清单。
- 合同兼容性检查。
- 渠道同步检查。
- 回滚计划。
- 客户沟通方案。

重难点：

- 已有商品变更比新上架更复杂，因为有存量客户、合同和账单。
- 退款和退订不是单一财务动作，会影响权益、账单、收入确认和客户成功。
- 变更必须先灰度，再巡检，再扩大。

练习问题：

- Agent Plan Medium 要调整套餐额度，会影响哪些客户、合同、账单和官网/控制台展示？
- Seedance Mini 要新增 Pro SKU，如何生成变更影响分析和审批摘要？

## 14. 发布后巡检与运营健康

本章目标：理解“上架成功”不等于“业务健康”。

发布后 24 小时要巡检：

- 官网展示是否正确。
- 控制台购买是否正常。
- 销售报价是否同步。
- 订单是否创建成功。
- 计量是否写入。
- 账单是否生成。
- 发票状态是否正常。
- 客户反馈是否异常。
- 告警和 SLA 是否触发。
- 经营指标是否偏离预期。

关键交付物：

- 发布后健康日报。
- 渠道一致性检查。
- 订单/计量/账单闭环校验。
- 客户反馈聚合。
- 风险和阻塞清单。
- 后续动作清单。

重难点：

- 价格和权益最容易出现渠道不一致。
- 订单成功不代表账单正确，计量和计费必须闭环。
- 发布后问题要能同步到 PM、SRE、销售、客服和老板视角。

练习问题：

- Seedance Mini 上架后 24 小时，官网、控制台、订单、计量、账单和客户反馈是否正常？
- 如果巡检发现控制台价和销售报价不一致，谁负责处理？

## 15. 续约、客户成功与增长

本章目标：理解云商品不是一次性交易，续约和扩容是经营核心。

续约关注：

- 到期时间。
- 当前 ARR。
- 续约概率。
- 用量健康。
- 账单争议。
- SLA 事故。
- 客户满意度。
- 竞品风险。
- 升级机会。
- 负责人和下一步动作。

关键交付物：

- 续约风险清单。
- 客户健康度评分。
- 销售跟进清单。
- 客户成功检查模板。
- 升级和扩容建议。
- 续约复盘。

主要负责人：

- 客户成功：客户健康和续约风险。
- 销售：合同推进和商务谈判。
- 财务：折扣和收入影响。
- 商品 PM：把客户反馈沉淀到产品和商品规则。
- 老板：关注 ARR、续约风险和增长目标。

重难点：

- 用量高不一定健康，可能意味着成本高、账单争议高或即将超额。
- 续约风险要能回连到商品问题、SRE 问题、账单问题和销售动作。

练习问题：

- 哪些重点云客户续约有风险，影响金额是多少？
- 我负责的客户里，本周最该跟进哪三个机会？

## 17. 对外客户场景

本章目标：把内部平台能力映射到客户旅程。

大客户场景：

- 需要解决方案和架构组合。
- 关注合同价、SLA、稳定性、审计和交付窗口。
- 需要容量预约、折扣审批和商务谈判。
- 常见产品组合：ECS GPU、RDS、TOS、CLB、CDN、AI 模型服务。

- 是否有升级或降级需求。

客户采购场景：

- 关注权限、额度、超额付费确认、通知人和预算上限。

练习问题：

## 18. 研发和平台实现视角

本章目标：让研发知道业务为什么这样设计，也让产品知道系统边界在哪里。

平台能力：

- Domain Pack：按业务域注册资源、工具、权限、路由和展示。
- Resource Config：定义表、字段、中文说明、主键和展示字段。
- Query Business Data：通用业务数据查询。
- Dedicated Tools：估算、评审、审批摘要、巡检、影响分析等专用工具。
- Permission Policy：客户、合同、账单、折扣等数据权限隔离。
- OpenUI Surface：把工具结果变成业务驾驶舱、流程图、表格、表单和标签。
- Eval：确保路由、权限、展示和字段中文化稳定。

研发要重点守住：

- 工程字段不能透出给用户。
- 写入类动作只生成草稿、模拟计划或审批摘要。
- 估算不能说成正式报价。
- demo/mock 不能说成官方承诺。
- 不同 domain 必须隔离。
- 客户只能看自己的数据。
- 所有高风险动作要可审计。

关键交付物：

- 数据字典。
- 工具契约。
- 权限策略。
- 路由规则。
- OpenUI 展示契约。
- 自动化验收用例。
- 浏览器 UAT 剧本。

重难点：

- Agent 不是写死剧本，而是通过路由、工具、数据和展示契约走 agentic loop。
- Prompt 只能约束部分行为，关键业务边界必须落到数据、权限、工具和测试。
- 展示层要服务用户阅读路径，先给结论、风险、动作，再给明细和证据。

练习问题：

- 为什么云商品和经销商 domain 必须前端和工具层都隔离？
- OpenUI 为什么需要 BusinessBriefSurface，而不是直接展示长表格？

## 19. 完整实战案例

本章目标：用真实故事把前面所有章节串起来。

案例 A：ECS GPU 训练实例

- 产品化：GPU 训练能力是否可包装成商品。
- 商品化：Product、Offer、SKU、Meter、Price、Region。
- 上架：IPD、财务毛利、SRE 容量、法务 SLA、GTM ready。
- 销售：金融客户 30 万预算，ECS GPU + RDS + TOS + CLB。
- 交付：新加坡容量不足导致延期。
- 经营：GMV 目标、毛利、pipeline、客户风险。
- 复盘：沉淀下一次上架模板。

案例 B：Seedance Mini 自助购买

- 产品化：模型能力变成可自助购买商品。
- Offer：按量、资源包、促销价、合同折扣互斥。
- SRE：大促队列、限流、告警、销售通知。
- GTM：活动页 FAQ、禁承诺项、数据边界。
- 客户：估算不等于正式报价。
- 巡检：上线后官网、控制台、订单、计量、账单闭环。

案例 C：Agent Plan 套餐权益

- 产品化：企业 Agent 套餐。
- 权益：每日赠送 Token、消耗顺序、过期、退订、超额付费。
- 财务：高成本模型和联网搜索导致毛利风险。
- 客户解释：额度用完不会自动扣费，需管理员二次确认。
- 续约：客户用量健康、账单争议和升级机会。

## 多视角完整性审查

从产品视角看，当前大纲已经覆盖产品化定义、商品主数据、生命周期、Offer/权益、渠道发布、GTM、经营复盘。还需要持续强化的是竞品分析、行业方案沉淀、商品版本策略和客户反馈闭环。

从研发视角看，当前大纲覆盖数据模型、权限、工具、OpenUI、eval 和 domain 隔离。还需要补充的是真实生产系统集成、幂等、审计日志、灰度发布、故障回放和可观测性。

从财务视角看，当前大纲覆盖 GMV、净收入、毛利、折扣、收入确认、资源包递延和退款退订。还需要补充的是税务、发票合规、跨境结算、多币种和渠道分佣。

从 SRE 视角看，当前大纲覆盖容量、限流、告警、灰度、回滚和 SLA。还需要补充的是容量预测、成本容量联动、压测基线、故障等级和演练机制。

从销售/GTM 视角看，当前大纲覆盖目标客户、方案、FAQ、禁承诺项、报价前检查。还需要补充的是竞品 battlecard、行业案例库、销售激励、渠道伙伴和 Marketplace 运营。

从客户视角看，当前大纲覆盖买前询价、正式报价边界、额度、账单、超额、续约。还需要补充的是采购流程、管理员权限、预算控制、多账号组织、服务工单和合规材料下载。

从老板/经营层视角看，当前大纲覆盖 GMV、毛利、目标达成、风险、负责人和下一步动作。还需要补充的是市场份额、产品覆盖率、客户结构、行业竞争力、长期留存和战略投入产出。
